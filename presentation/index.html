01 · PROBLEMA Y USUARIO

Formatear documentos consume horas y rompe la estructura

PrettyDocs
● Problema actual
  • Los borradores en Word mezclan títulos falsos, listas manuales con glifos y estilos rotos.
  • Aplicar normas como APA 7 o formatos de reporte a mano es lento y propenso a errores.
● Usuario objetivo
  • Para quién: Estudiantes universitarios, docentes, investigadores y redactores técnicos.
  • Necesidad: Obtener un .docx profesional y navegable sin alterar su contenido.

02 · SOLUCIÓN

Dos modos de formateo sobre un mismo flujo

PrettyDocs

Modo Plantilla

use_ai: false
  • Formateo visual síncrono inmediato sobre el .docx original (HTTP 200).
  • Aplica márgenes, tipografía, interlineado y estilos sin cambiar la estructura.

Modo Inteligente

Sprint 3 · use_ai: true
  • Detecta títulos, listas, tablas y énfasis mediante IA (OpenRouter) o respaldo heurístico.
  • Procesamiento asíncrono (HTTP 202) con vista previa interactiva y reversión por bloque.
Presets estructurales incluidos (templates_engine/presets/):

Salida IA (AIChunkOutput)JSON Schema
{"type": "heading", "level": 1, "src": ["b3"],
 "runs": [{"text": "1. RESUMEN"}]}
{"type": "keep", "id": "b5", "src": ["b5"]}
  • Extractor v2: IDs estables y pistas (size_ratio, negrita, glifos).
  • Chunker: fragmentos de ~8k chars con heading_path (máx. 60k).
  • Bloques keep: clonados intactos desde el XML original.
Elementos blindados por keep
✓ Imágenes
✓ Tablas previas
✓ Secciones
✓ Encabezados y pies

09 · RIESGOS Y MITIGACIÓN

Principales riesgos técnicos mitigados en código

PrettyDocs
Integridad del contenido
Alto
Riesgo: La IA altera palabras, cifras o reescribe oraciones.
Mitigación: Validador estricto + 1 reintento + respaldo heurístico.
Fidelidad del paquete .docx
Alto
Riesgo: Pérdida de imágenes, tablas previas o secciones del Word.
Mitigación: Clonado XML sobre original + bloques opacos keep.
Acoplamiento de equipo
Medio
Riesgo: Bloqueo entre Frontend y Backend durante el Sprint 3.
Mitigación: Contrato API v1.1 + catálogo de mocks desde el día 1.
Infraestructura asíncrona
Medio
Riesgo: Complejidad de desplegar Celery y Redis en Windows.
Mitigación: JobRunner desacoplado con backend por hilos (thread / sync).
